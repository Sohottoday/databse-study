# ORA-19624

operation failed, retry possible

## 1. 개요

ORA-19624는 Oracle의 백업 복구 작업 중 특정 작업이 실패했지만 재시도할 수 있음을 나타내는 메시지이다.
주로 RMAN(Recovery Manager)을 이용한 Backup, Restore, Recovery 작업 과정에서 나타난다.

> ORA-19624: operation failed, retry possible

중요한 점은 ORA-19624 자체가 근본 원인을 설명하는 오류는 아니라는 것이다.
대부분 다른 ORA 오류와 함께 발생하며, 함께 출력된 오류를 확인해야 실제 장애 원인을 파악할 수 있다.

## 2. 의미

- 현재 수행하던 백업 복구 작업이 실패했지만, 오류 원인을 해결한 후 해당 작업을 다시 시도할 수 있다.

예를 들어 RMAN 백업 중 다음과 같이 발생할 수 있다.

```text
ORA-19502: write error on file "/backup/prod_01.bkp"
ORA-27072: File I/O error
ORA-19624: operation failed, retry possible
```

이 경우 실제 원인은 ORA-19502, ORA-27072 등이고, ORA-19624는 해당 작업이 실패했으며 재시도가 가능하다는 것을 알려주는 후속 메시지이다.
따라서 장애 분석 시 ORA-19624만 확인해서는 안된다.

## 3. 주요 발생 원인

### 3.1 백업 저장공간 부족

RMAN 백업 중 Backup Destination의 공간이 부족해질 수 있다.

```text
RMAN Backup
    ↓
Backup File 생성
    ↓
Disk 공간 부족
    ↓
Write 실패
    ↓
ORA-19624
```

특히 FRA(Fast Recovery Area)를 사용하는 환경이라면 FRA 사용률도 확인해야 한다.

### 3.2 Storage I/O 오류

백업 또는 복구 과정에서 Oracle이 파일을 정상적으로 읽거나 쓰지 못한 경우이다.

가능한 원인

- Disk 장애
- SAN/NAS 장애
- NFS 문제
- File System 오류
- Mount 해제
- 일시적인 I/O 장애

이 경우 ORA-195XX, ORA-270XX 또는 OS 오류가 같이 발생하는 경우가 많다.

### 3.3 RMAN Backup 실패

RMAN에서 다음 작업을 수행하다 실패할 수 있다.

- Database Backup
- Archivelog Backup
- Control File Backup
- SPFILE Backup
- Incremental Backup

이 경우 ORA-19624보다 앞뒤에 발생한 RMAN/ORA 오류를 먼저 확인해야 한다.

### 3.4 Restore 작업 중 파일 접근 실패

```text
RESTORE DATABASE;
또는
RESTORE DATAFILE 5;
```

수행 중 필요한 Backup Piece에 접근하지 못하면 발생할 수 있다.

가능한 원인 :

- Backup Piece 삭제
- Backup 경로 변경
- Storage 접근 불가
- Backup Piece 손상
  권한 문제

### 3.5 Recovery 작업 실패

```text
RECOVER DATABASE;
```

수행 중 필요한 Archived Redo Log 등에 접근하지 못하거나 복구 과정에서 I/O 문제가 발생하면 관련 오류와 함께 ORA-19624가 발생할 수 있다.

### 3.6 백업 파일 손상

Backup Piece 자체가 손상되어 Restore/Recovery 과정에서 읽지 못하는 경우이다.
RMAN VALIDATE 등을 통해 백업 또는 데이터파일의 상태를 점검할 필요가 있다.

### 3.7 권한 및 경로 문제

Oracle 프로세스가 백업 경로에 접근하지 못하는 경우이다.
예:

- Directory 권한 변경
- 소유자 변경
- Mount Point 변경
- Backup Directory
- NFS Mount 실패

## 4. 확인 방법

### 4.1 ORA-19624 전후 오류 확인

가장 먼저 해야 할 작업니다.

```text
ORA-19502: write error on file ...
ORA-27072: File I/O error
ORA-19624: operation failed, retry possible
```

이 경우 분석 대상은 ORA-19502, ORA-27072이다.
따라서 RMAN 로그에서 ORA-19624 직전의 오류 메시지까지 함께 확인해야 한다.

### 4.2 RMAN 백업 상태 확인

```SQL
SELECT session_key,
    input_type,
    status,
    start_time,
    end_time
FROM v$rman_backup_job_details
ORDER BY start_time DESC;
```

STATUS에서 다음과 같은 상태를 확인한다.

- COMPLETED
- COMPLETED WITH WARNINGS
- FAILED

### 4.3 Disk 사용량 확인

Linux 환경:

```bash
df -h
```

확인 항목:

- Backup Destination
- FRA
- Archive Log 영역
- Oracle Data 영역

### 4.4 FRA 사용량 확인

```SQL
SELECT name,
    space_limit,
    space_used,
    space_reclaimable,
    number_of_files
FROM v$recovery_file_dest;
```

FRA 내부 사용 현황:

```SQL
SELECT file_type,
    percent_space_used,
    percent_space_reclaimable,
    number_of_files
FROM v$flash_recovery_area_usage;
```

### 4.5 RMAN Backup Piece 확인

RMAN에서 :

```text
LIST BACKUP SUMMARY;
```

상세 확인 :

```text
LIST BACKUP;
```

### 4.6 Backup 상태 검증

```text
VALIDATE BACKUPSET <backupset_number>;

또는 데이터베이스 검증
VALIDATE DATABASE;
```

### 4.7 Alert Log 및 OS 로그 확인

다음을 함께 확인한다.

- Oracle Alert Log
- RMAN Log
- OS System Log
- Storage Log
- SAN/NAS 상태

특히 ORA-270XX가 같이 발생했다면 OS/Storage 계층까지 확인하는 것이 중요하다.

## 5. 조치 방법

### 5.1 Disk 공간 부족인 경우

불필요한 파일을 정리하거나 Backup Destination을 증설한다.

FRA를 사용한다면 다음을 검토한다.

- 오래된 Archive Log 정리
- 불필요한 Backup 정리
- FRA 크기 증설

공간 확보 후 RMAN 작업을 재시도한다.

### 5.2 Storage 장애인 경우

다음을 확인한다.

- Storage 연결 상태
- Mount 상태
- Disk 상태
- SAN/NAS 상태
- File System 오류

Storage 문제가 해결된 이후 Backup/Restore 작업을 수행한다.

### 5.3 Backup Piece가 손상된 경우

정상적인 다른 Backup Piece가 존재하는지 확인한다.

```text
LIST BACKUP;
```

필요하면 다른 정상 Backup을 이용하여 Restore를 수행한다.

### 5.4 Backup 경로 문제인 경우

OS에서 경로 및 권한을 확인한다.

```bash
ls -ld /backup

ls -l /backup
```

Oracle 계정이 해당 경로를 읽고 쓸 수 있는지 확인한다.

## 6. 장애 분석 시나리오

### 시나리오 1. RMAN 백업 중 ORA-19624 발생

가능성

- Backup Destination 공간 부족
- FRA 공간 부족
- Storage I/O 오류
- 백업 경로 접근 실패
- File System 문제

조치

1.  RMAN 로그에서 ORA-19624 직전 오류 확인
2.  V$RMAN_BACKUP_JOB_DETAILS 에서 실패한 백업 확인
3.  df -h 로 저장공간 확인
4.  FRA 사용률 확인
5.  Storage 및 Mount 상태 확인
6.  원인 해결 후 RMAN Backup 재수행

### 시나리오 2. Restore 중 ORA-19624 발생

가능성

- Backup Piece가 존재하지 않음
- Backup Piece 손상
- Backup Storage 접근 실패
- 파일 권한 문제
- Storage I/O 오류

조치

1.  RMAN 로그의 선행 ORA 오류 확인
2.  LIST BACKUP SUMMARY 로 백업 존재 여부 확인
3.  Backup Piece 실제 파일 존재 여부 확인
4.  RMAN VALIDATE 수행
5.  Storage 상태 확인
6.  필요 시 다른 정상 Backup으로 Restore

### 시나리오 3. Archivelog 백업 중 ORA-19624 발생

가능성

- Archive Destination 공간 부족
- FRA 공간 부족
- Archive Log 파일 접근 실패
- Archive Log가 OS에서 삭제됨
- Storage 문제

존재

1.  실패한 RMAN 작업 확인
2.  Archive Log 상태 확인
3.  FRA 사용률 확인
4.  실제 Archive Log 파일 존재 여부 확인
5.  RMAN Repository와 실제 파일 상태 비교
6.  원인 해결 후 Archivelog Backup 재수행

### 시나리오 4. ORA-195XX / ORA-270XX와 함께 ORA-19624 발생

가능성

- File I/O 오류
- OS File System 문제
- Disk/SAN/NAS 장애
- 파일 권한 문제
- 저장공간 부족

조치

1.  ORA-19624보다 먼저 발생한 ORA-195XX 확인
2.  ORA-270XX 및 OS Error 확인
3.  Disk 공간 확인
4.  File System 및 Mount 상태 확인
5.  Storage 담당자와 장애 여부 확인
6.  원인 해결 후 작업 재수행

## 7. 관련 SQL

```SQL
SELECT session_key,
    input_type,
    status,
    start_time,
    end_time,
    elapsed_seconds
FROM v$rman_backup_job_details
ORDER BY start_time DESC;
```

```SQL
SELECT session_key,
    input_type,
    status,
    start_time,
    end_time
FROM v$rman_backup_job_details
WHERE status LIKE '%FAILED%'
```

## 8. 예방 방법

- RMAN 백업 결과 정기 확인
- FRA 사용률 모니터링
- Backup Destination 용량 모니터링
- Storage I/O 상태 모니터링
- Backup Piece 정기 검증
- RMAN VALIDATE 정기 수행
- 백업 파일 임의 삭제 방지
- Archive Log 관리 정책 수립
- 백업 실패 알림 구성
- RMAN 로그와 Alert Log 보관
- 백업뿐 아니라 실제 Restore 테스트도 정기적으로 수행

## 9. 정리

ORA-19624는 RMAN 등의 백업 복구 작업이 실패했지만 재시도할 수 있음을 알려주는 메시지이다.
핵심은 함께 발생한 성행 오류를 확인하는 것이다.

- ORA-19502 -> 파일 Wirte 실패
- ORA-27072 -> OS/File I/O 계층 오류
- ORA-19624 -> 해당 작업 실패 및 재시도 가능

따라서 실무에서는 ORA-19624 발생 -> 선행 ORA 확인 -> RMAN 작업 확인 -> Disk/FRA/Storage 확인 -> 원인 제거 -> Backup/Restore 재시도 순서로 접근하는 것이 적절하다.
