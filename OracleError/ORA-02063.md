# ORA-02063 : preceding line from database_link

> 실제 현업 메시지
> ORA-02063 : line가 선행됨(xxxx로부터)
> DBA님이 DB link로 연결된 원격 DB에서 ORA-04063 오류가 발생하였고, 그게 내 쪽으로 전달된 것이라 함.

## 1. 개요

ORA-02063은 Database Link(DB Link)를 통해 원격 데이터베이스와 통신하는 과정에서 발생한 오류의 출처를 알려주는 정보성 메시지이다.
이 오류는 단독으로 발생하는 경우는 거의 없으며, 대부분 다른 Oracle 오류와 함께 출력되어 어느 원격 데이터베이스(Database Link)에서 오류가 발생했는지를 알려주는 역할을 한다.

Oracle 공식 설명은 다음과 같다.

> ORA-02063 : preceding line from string = 앞에 출력된 오류가 지정된 Database Link(원격 데이터베이스)에서 발생했음을 의미
> 즉, ORA-02063 자체가 장애의 원인은 아니다.

## 2. 의미

Oracle 에서 Database Link를 이용해 원격 DB에 SQL을 수행하던 중, **"바로 앞의 ORA 오류는 이 Database Link(원격DB)에서 발생했습니다."** 라는 정보를 제공하는 메시지이다.

```text
ORA-00942 : table or view does not exist
ORA-02063 : preceding line from HR_LINK
```

실제 원인은 ORA-00942이며, ORA-02063은 HR-LINK 라는 DB Link에서 발생했다는 것을 알려준다.

## 3. 주요 발생 원인

### 3.1 원격 DB에서 실제 ORA 오류 발생(가장 흔함)

```text
ORA-01017 : invalid username/password
ORA-02063 : preceding line from PROD_LINK
```

실제 원인은 '계정 비밀번호 오류' 이다.

### 3.2 원격 객체(Table/View) 없음

```text
ORA-00942
ORA-02063
```

가능성

- 테이블 삭제
- View 삭제
- Synonym 삭제
- Schema 변경

### 3.3 권한 부족

```text
ORA-01031
ORA-02063
```

가능성

- SELECT 권한 없음
- EXECUTE 권한 없음
- INSERT 권한 없음

### 3.4 Database Link 연결 문제

```text
ORA-12154
ORA-02063

또는

ORA-12514
ORA-02063
```

가능성

- Listener 문제
- TNS 설정 오류
- 네트워크 장애
- DB Link 설정 오류

### 3.5 원격 DB 장애

가능성

- Instance Down
- Database Shutdown
- Listener Down
- Storage 장애
- 네트워크 장애

### 3.6 원격 SQL 오류

```text
ORA-00904
ORA-02063
```

가능성

- 컬럼명 오류
- 함수 오류
- SQL 문법 오류
- 패키지 오류

## 4. 확인 방법

### 4.1 ORA-02063 바로 위의 ORA 오류 확인

보통 ORA-02063 바로 위의 ORA 오류가 실제 오류인 경우가 많다.

### 4.2 DB Link 정보 확인

```sql
SELECT owner,
    db_link,
    username,
    host
FROM dba_db_links;
```

### 4.3 DB Link 연결 테스트

```sql
SELECT *
FROM dual@DB_LINK명;
```

정상이라면 X 가 조회된다.

### 4.4 Listener 상태 확인

원격 서버에서

```bash
lsnrctl status
```

확인 항목

- Listener 기동 여부
- Service 등록 여부
- Port 정상 여부

### 4.5 TNS 연결 확인

OS에서

```bash
tnsping 서비스명

또는

sqlplus 계정/비밀번호@서비스명
```

으로 접속 테스트를 수행

### 4.6 Alert Log 확인

원격 DB의 Alert Log를 확인한다.

확인항목

- ORA 오류
- Listener 오류
- Instance Down
- Storage 오류
- Recovery 여부

## 5. 조치 방법

### 5.1 실제 ORA 오류 해결

가장 먼저 ORA-02063 바로 앞의 ORA 오류를 해결한다.

### 5.2 DB Link 연결 확인

다음을 확인한다.

- Host
- Port
- Service Name
- Username
- Password

### 5.3 Listener 확인

원격 DB Listener가 정상인지 확인한다.

필요 시

```bash
lsnrctl start

또는

lsnrctl reload
```

를 수행한다.

### 5.4 네트워크 확인

다음을 확인한다.

- Ping
- Firewall
- VPN
- DNS
- Routing

### 5.5 권한 확인

원격 DB에서 권한을 확인한다.

- SELECT
- INSERT
- UPDATE
- EXECUTE

## 6. 장애 분석 시나리오

### 6.1 시나리오 1. ORA-00942와 함께 ORA-02063 발생

가능성

- 원격 DB에 테이블이 존재하지 않음
- View 삭제
- Synonym 변경
- Schema 변경

조치

1.  ORA-00942 확인
2.  원격 DB에서 테이블 존재 여부 확인
3.  Synonym 확인
4.  Schema 변경 여부 확인

### 6.2 시나리오 2. ORA-01017과 함께 ORA-02063 발생

가능성

- DB Link 계정 비밀번호 변경
- 계정 잠금
- 계정 만료

조치

1.  DB Link 계정 확인
2.  원격 DB 로그인 테스트
3.  비밀번호 변경 여부 확인
4.  DB Link 재생성 검토

### 6.3 시나리오 3. ORA-12154 또는 ORA-12514와 함께 ORA-02063 발생

가능성

- Listener 장애
- TNS 설정 오류
- Service Name 변경
- 네트워크 장애

조치

1.  tnsping 수행
2.  Listener 상태 확인
3.  tnsnames.ora 설정 확인
4.  Service Name 확인
5.  네트워크 연결 확인

### 6.4 시나리오 4. 특정 시간에만 ORA-02063 발생

가능성

- 원격 DB 재기동
- 야간 점검
- 네트워크 불안정
- Listener 재시작
- 방화벽 정책 적용

조치

1.  발생 시간 확인
2.  원격 DB 점검 이력 확인
3.  Alert Log 확인
4.  Listener 로그 확인
5.  네트워크 로그 확인

## 7. 관련 SQL

### DB Link 조회

```sql
SELECT owner,
    db_link,
    username,
    host
FROM dba_db_links;
```

### DB Link 테스트

```sql
SELECT *
FROM dual@DB_LINK명;
```

### Public DB Link 조회

```sql
SELECT db_link,
    username,
    host
FROM dba_db_links
WHERE owner = 'PUBLIC';
```

### 현재 Database Link 사용 여부 확인

```sql
SELECT db_link,
    in_transaction,
    update_sent
FROM v$dblink;
```

### 원격 테이블 조회 예시

```sql
SELECT *
FROM EMP@HR_LINK;
```

## 8. 예방 방법

- DB Link 게정 비밀번호 변경 시 DB Link도 함께 갱신
- Listener 상태 모니터링
- TNS 설정 변경 시 영향도 검토
- 원격 DB 점검 일정 공유
- DB Link 연결 테스트 정기 수행
- 원격 객체(Table/View/Synonym) 변경 시 사전 검증
- Alert Log 및 Listener Log 모니터링

## 9. 정리

ORA-02063은 Database Link를 통해 원격 데이터베이스에서 발생한 오류의 위치를 알려주는 정보성 메시지이다.
따라서, ORA-02063 자체를 해결하는 것이 아니라, 바로 앞에 출력된 ORA 오류를 해결해야 한다.
대부분의 경우 원인은 원격 DB의 권한 문제, 객체 누락, 네트워크 문제, Listener 문제, 계정 문제 등에 있다.

SI 운영 환경에서는 여러 시스템(DB)이 DB Link로 연결된 경우가 많으므로, 어느 시스템에서 DB Link인지(ERP, 그룹웨어, DW, 타 시스템 등) 까지 함께 확인하면 원인 파악 속도를 크게 높일 수 있습니다.
